The pair chart — three mockups

All three draw the same payload. Legend everywhere: ■ CE 24500   ■ PE 24400   ■ BUY rotation   ■ structure (VWAP/σ). Gaps in a leg stay gaps — the axis join rule says a missing bar is never faked from a neighbour, so the mockups show one (PE, 11:00–11:06).

AStacked legs, shared clock

CE premium tape above, PE below, one time axis (axis). Each leg carries its own VWAP + 1σ/2σ shading (legs.*.vwap, bands from the same contract_bars.vwap_sigma the tape already uses). Rotation records (rotation[i]) land as chips in the spine between the panes — they belong to the PAIR, not to a leg. Right rail: the two verbatim receipts (pair_why, rotation[i].trigger) plus live OI.

Trade-off: most honest to the data (nothing overlaps, gaps are visible), costs the most vertical space. Closest to what LegChart.tsx already renders — cheapest to build.

BMirror — PE grows downward

Same two legs, but PE's premium axis is flipped so both legs grow outward from a central spine. The whole point of the pair is divergence — one book paying up while the other bleeds — and here divergence is literal asymmetry you can see across the spine. Rotation chips sit ON the spine. σ bands drawn per leg, mirrored.

Trade-off: the divergence read is instant, but premium LEVELS are harder to read on the flipped leg, and a mirrored chart is a new idiom to learn. Same build cost as A plus a flipped scale.

COverlay + OI ribbons

Both legs as close-lines in ONE pane, each normalised to its session open (premium %, since a 24500CE and 24400PE never share a rupee scale). Below: each leg's OI slope as a ribbon (legs.*.oi deltas) — writers adding / evacuating is exactly what the two-leg confirm reads. Under that, the index compression strip (index_series bandwidth, deliberately un-aligned per INDEX_SERIES_RULE).

Trade-off: most information per pixel and the OI story is explicit — but normalised % hides absolute premium (your stop is in rupees), and candles are gone. Highest build cost: new ribbon component + normalisation logic.

If one of these gets a yes, the build is

  • A PairChart.tsx panel inside the existing TradeTab, reusing LegChart.tsx's candle/band machinery — no new chart engine.
  • One fetch of /api/contract?idx=…&interval=3 per refresh cycle, same cadence as the tape; pair is chosen server-side by pick_pair, no strike UI needed on day one.
  • Receipts rendered VERBATIM (house rule: quoted so they can be checked against the candle, not trusted).
  • The already-written but unreachable ~850-line backend stack finally gets its consumer; nothing in live.py changes.
